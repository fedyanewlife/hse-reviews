# Использовать монолитную архитектуру

## Статус

Принято.

## Контекст

Проект разрабатывается командой из двух человек.
Приоритет — простота разработки и развёртывания приложения.
Ожидаемая нагрузка не требует независимого масштабирования отдельных функций.

## Решение

Реализовать всю бизнес-логику в одном приложении, которое собирается и развёртывается как единое целое.
Микросервисное разделение отклонено из-за дополнительных затрат на развёртывание и сопровождение при текущем составе команды.

## Последствия

- Упрощаются запуск, развёртывание и отладка по сравнению с микросервисной архитектурой.
- Изменения кода монолитного приложения выпускаются в составе приложения целиком.
- Для масштабирования отдельных функций требуется масштабировать всё приложение.
