# Использование Structurizr DSL для ведения C4-диаграмм

## Статус

Предложено.

## Контекст

Для документирования архитектуры необходимо спроектировать C4-диаграммы уровней 1–3 (Context, Container, Component).
Диаграммы должны храниться в репозитории и быть доступны для просмотра на GitHub.
Исходные файлы должны быть сохранены для быстрого редактирования диаграмм.

Рассмотрены три подхода к проектированию и редактированию C4-диаграмм:

1. Создание схем в draw.io.
2. Описание диаграмм в Mermaid.
3. Описание архитектуры в Structurizr DSL.

Для просмотра на GitHub рассматривались изображения, блоки Mermaid в Markdown и публикация на GitHub Pages.

## Решение

Следовать подходу Architecture as Code.
Описывать архитектуру проекта в Structurizr DSL, хранить редактируемую модель в Git и генерировать из неё C4-диаграммы.

Отображать диаграммы в `docs/c4/README.md`.
Использовать изображения `.svg` для сохранения стилей Structurizr DSL.
Текстовая модель позволяет видеть изменения элементов и связей прямо в репозитории.
```text
docs/
└── c4/
    ├── diagrams/
    │   ├── 1-context.svg
    │   ├── 2-container.svg
    │   └── 3-component.svg
    ├── compose.yaml
    ├── README.md
    └── workspace.dsl
```

Использовать конфигурацию Docker Compose для локального экспорта изображений и проверки соответствия в GitHub Actions.
При проверке повторно генерировать диаграммы из модели и сравнивать результат с сохранёнными файлами.

Поддержка стилей Structurizr DSL в Mermaid ограничена.
Схемы в draw.io редактируются визуально, автоматический экспорт потребовал бы дополнительной настройки.
Для просмотра диаграмм достаточно README в репозитории, поэтому публикация через GitHub Pages избыточна.

## Последствия

- Модель DSL стандартизирована, её можно быстро редактировать и просматривать как текст.
- Общие элементы и связи описываются один раз и переиспользуются в диаграммах всех уровней.
- В репозитории хранятся модель и сгенерированные изображения, а CI проверяет их соответствие.
- Для локального экспорта требуется Docker.
