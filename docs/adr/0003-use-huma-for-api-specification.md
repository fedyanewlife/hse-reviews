# Использование Huma для генерации спецификации API

## Статус

Предложено.

## Контекст

Необходимо явно вести спецификацию API и поддерживать её в актуальном состоянии.
Рассмотрены три способа ведения спецификации:
1. Ручное ведение документации в файле `docs/openapi.yaml`.
2. Генерация спецификации из комментариев к функциям с помощью Swagger.
3. Использование фреймворка Huma.

## Решение

Использовать Huma для генерации спецификации API.
Источником истины считать Go-код: регистрацию операций, типы входных и выходных значений.

Ручное ведение `openapi.yaml` отклонено из-за необходимости синхронизировать спецификацию с кодом.
Генерация из комментариев отклонена из-за объёма аннотаций и дублирования описаний операций.

## Последствия

- Схемы запросов и ответов формируются из Go-описаний и обновляются автоматически.
- Сокращается объём кода для получения и валидации входных данных и отправки ответов.
- Существующие обработчики требуется адаптировать к Huma.
- Появляется зависимость от стороннего фреймворка Huma.
