# Фронтенд ОтзоВышки

React + TypeScript + Vite.

## Запуск

Нужен Node.js 20.19+ (или 22.12+).

```sh
npm install
npm run dev        # http://localhost:5173
```

В режиме разработки запросы `/auth/*`, `/me/*`, `/health`, `/minors/*`, `/reviews` проксируются на бэкенд `http://localhost:8080`
(другой адрес — через переменную `BACKEND_URL`). Фронтенд и API должны жить на одном origin:
сессия хранится в HttpOnly-cookie.

## Главная страница

`http://localhost:5173/catalog` (или `/home`)
Авторизация остаётся по адресу `/`

При `npm run dev` по умолчанию включён режим `demo`: каталог работает без Go, Docker и входа.
Доступны поиск по названию, направлению и факультету, фильтры, сортировка, избранное,
просмотр примеров отзывов и раскрытие следующих карточек. Клавиши Ctrl+K / Cmd+K
переводят фокус в поиск. Избранное и отзывы из раздела «Мои отзывы» хранятся только
в localStorage этого браузера; они не отправляются на сервер и не публикуются.

Состояния можно посмотреть отдельно:

- `/catalog?state=empty` — пустая выдача с действующим сбросом поиска и фильтров;
- `/catalog?state=loading` — skeleton списка (включая вариант без анимации при reduced motion).

Данные примеров — `src/features/catalog/catalogDemo.ts`. Демо-репозиторий загружается
динамически. Компоненты используют общий интерфейс `CatalogRepository`.

## Страница майнора

`/disciplines/data-analysis` — пример отдельной страницы в demo-режиме.
Карточки каталога и баннера избранного ведут на `/disciplines/:id`; в API-режиме id числовой.
Ссылки на разделы каталога: `/catalog?view=favorites` и `/catalog?view=reviews`.

На странице доступны оценки по четырём критериям, распределение рекомендаций, советы
из отзывов, фильтры по статусу прохождения, сортировка и избранное. Кнопка «Оставить отзыв»
открывает `/review/new?minor=:id` с выбранным майнором. Отметки «Полезно» работают только
в demo и сохраняются локально.

Примеры полных ответов анкеты — `src/features/discipline/disciplineDemo.ts`.
Демо-репозиторий рассчитывает из них общие для каталога и страницы майнора числа отзывов
и рейтинг. В API-режиме примеры не подставляются вместо отсутствующих данных.

## Мои отзывы

`/catalog?view=reviews` — личный отзыв с отдельным мятно-голубым баннером.
В баннере отображается фрагмент своего отзыва; ниже — рекомендация, четыре оценки,
впечатления, совет и статус. Данные личного отзыва загружаются независимо от избранного.
Пустое состояние, загрузка и ошибка не подменяются примером отзыва.

Пользователь может оставить отзыв только об одном майноре. Клиент блокирует второй
активный отзыв и отправку отзыва на другой майнор; после отклонения допускается повторная
отправка на тот же майнор. Прежние записи остаются в свёрнутой истории отправок.
Для отклонённого отзыва доступно исправление с повторной отправкой на тот же майнор.
Редактирование опубликованных и ожидающих проверки отзывов пока не предусмотрено.

Для просмотра заполненного экрана без бэкенда (только demo, если нет сохранённого отзыва):

- `/catalog?view=reviews&reviewPreview=published` — опубликован;
- `/catalog?view=reviews&reviewPreview=pending` — на проверке;
- `/catalog?view=reviews&reviewPreview=rejected` — отклонён с комментарием модератора;
- `/catalog?view=reviews&reviewPreview=local` — сохранён только в браузере.

Примеры помечены в интерфейсе, не записываются в localStorage и игнорируются в API-режиме.
Число отметок «Полезно» и даты показываются только при наличии соответствующих данных.

## Форма отзыва

`/review/new` — выбор майнора; `/review/new?minor=data-analysis` — майнор подставлен.
Форма открывается из баннера каталога, пустого раздела «Мои отзывы» и страницы майнора.
При существующем активном отзыве показывается ссылка на него, без возможности отправить второй.

Обязательны майнор, статус прохождения, пять оценок от 1 до 5 и согласие на анонимную
публикацию. Впечатления и совет необязательны, каждый текст — до 4000 символов.
Предпросмотр обновляется по мере заполнения. В demo отзыв сохраняется только локально;
в API-режиме отправляется `POST /reviews`, затем показывается полученный статус.
При ошибке текст остаётся в форме. Срок проверки в интерфейсе не обещается.

Черновик сохраняется в sessionStorage текущей вкладки; demo и API используют разные ключи.
Согласие из черновика не восстанавливается. После успешной отправки черновик удаляется,
при выходе из аккаунта удаляется API-черновик. Ошибка хранилища не блокирует заполнение.
Статус прохождения требует поддержки `completion_status` на API — см. `API.md`.

## Подключение API

HTTP-адаптер уже реализован в `src/features/catalog/catalogApi.ts`. Для его включения
создайте `.env.local` по образцу `.env.example`, установите `VITE_CATALOG_MODE=api`
и перезапустите Vite. Production-сборка без переопределения режима по умолчанию использует API.

Проверка логики каталога: `npm test`.

## Скрипты

| Команда                | Что делает                                   |
| ---------------------- | -------------------------------------------- |
| `npm run build`        | проверка типов и production-сборка в `dist/` |
| `npm run preview`      | локальный просмотр собранной версии          |
| `npm run typecheck`    | только проверка типов                        |
| `npm test`             | логика каталога и контракт HTTP-адаптера     |
| `npm run lint`         | ESLint                                       |
| `npm run format`       | Prettier                                     |
| `npm run format:check` | проверка форматирования (для CI)             |

## Структура

```
src/
  components/ui/   примитивы дизайн-системы: Button, IconButton, TextField, SearchField, DirectionMark
  features/        auth — вход, catalog — главная/данные, discipline — майнор/отзывы,
                   my-reviews — личный отзыв, review-form — форма, theme — тема
  shared/api/      HTTP-клиент, ошибки и адреса эндпоинтов
  lib/             общие хелперы и хуки
  styles/tokens/   токены дизайн-системы: цвета, типографика, отступы
```

Шрифты (Manrope, Unbounded) и иконки (Lucide) подключаются из npm-пакетов, внешние CDN не используются.
