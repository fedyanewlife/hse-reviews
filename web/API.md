# Подключение каталога к бэкенду

Фронтенд готов работать через HTTP-адаптер `src/features/catalog/catalogApi.ts`.
Данные каталога и опубликованных отзывов проходят через `CatalogRepository`.
Демонстрационная и HTTP-реализации имеют один интерфейс.

## Режимы и запуск

- `npm run dev` без настройки `VITE_CATALOG_MODE` использует `demo`.
- `npm run build` без этой настройки использует `api`.
- Для явного выбора скопировать `.env.example` в `.env.local` и указать
  `VITE_CATALOG_MODE=demo` либо `VITE_CATALOG_MODE=api`. После изменения перезапустить Vite.
- `BACKEND_URL` задаёт адрес сервера для dev-прокси, по умолчанию `http://localhost:8080`.
- Пустой `VITE_API_BASE_URL` означает запросы на тот же origin. Это рекомендуемая схема.
  Для сервера за префиксом можно указать, например, `/api`.

Адреса UI: `/` — существующая авторизация, `/catalog` или `/home` — главная.
`/disciplines/:id` — отдельная страница майнора; `/catalog?view=favorites` и
`/catalog?view=reviews` — разделы каталога.
`?state=empty` и `?state=loading` действуют только в demo-режиме.
HTTP-режим никогда автоматически не переключается на примеры при ошибке.

Запросы передают cookie с `credentials: include`. Токены в localStorage не сохраняются.
При 401 интерфейс предлагает вернуться на страницу входа. Отмена загрузки передаётся
в `fetch` через `AbortSignal`; неудачные POST не повторяются автоматически.

## Что уже есть и что требуется от бэкенда

| Маршрут                     | Состояние текущего Go-кода           | Требуется                                         |
| --------------------------- | ------------------------------------ | ------------------------------------------------- |
| `GET /minors`               | `{ items: [{ id, name, hse_url }] }` | Расширить карточку полями ниже                    |
| `GET /minors/{id}/reviews`  | Реализован                           | Существующий ответ поддержан адаптером            |
| `GET /me/reviews`           | Реализован                           | Существующий ответ поддержан адаптером            |
| `POST /reviews`             | Реализован                           | Существующий запрос и `{ id, status }` поддержаны |
| `POST /auth/logout`         | Реализован                           | Существующий маршрут поддержан                    |
| `GET /me/favorites`         | Отсутствует                          | Добавить список числовых id                       |
| `PUT /me/favorites/{id}`    | Отсутствует                          | Идемпотентно добавить в избранное                 |
| `DELETE /me/favorites/{id}` | Отсутствует                          | Идемпотентно убрать из избранного                 |

Серверные файлы этой задачей не изменяются. Недостающие метаданные не подменяются
придуманными значениями: неполный ответ вызывает контролируемую ошибку контракта.

## GET /minors

Обёртка `{ items: [] }` и поля `id`, `name`, `hse_url` сохраняются. Пример одной записи:

```json
{
  "items": [
    {
      "id": 42,
      "name": "Интеллектуальный анализ данных",
      "hse_url": "https://electives.hse.ru/minor_intel/",
      "direction": "it",
      "faculty": "Факультет компьютерных наук",
      "faculty_label": "ФКН",
      "rating": 4.6,
      "review_count": 128,
      "review_preview": { "rating": 5, "text": "Много практики на Python." }
    }
  ]
}
```

- `id`: положительный int32, как в существующем API. В UI приводится к строке.
- `name`, `faculty`: строки. `faculty_label`: необязательная короткая подпись или `null`.
- `direction`: `it` (ИТ), `biz` (Бизнес), `soc` (Общество), `cult` (Культура),
  `edu` (Образование). Это полный список групп майноров; подписи и цвета задаёт фронтенд.
- `rating`: число от 1 до 5 либо `null`, если оценок нет. `0` не используется вместо отсутствующей оценки.
- `review_count`: целое число опубликованных отзывов, минимум 0.
- `review_preview`: один опубликованный отзыв `{ rating, text }` либо `null`.
  `rating` в превью — оценка готовности рекомендовать.

Для этого контракта итоговый `rating` — среднее `recommendation_rating` опубликованных
отзывов. Это соглашение для интеграции, а не реализованная сейчас агрегация в Go.
Чужие неопубликованные отзывы и данные авторов в каталог не попадают.

Текущий размер каталога позволяет загрузить полный список один раз. Поиск, фильтры,
сортировка и раскрытие по 6 карточек выполняются на клиенте. Серверная пагинация пока
не заявлена этим контрактом; при её добавлении нужно менять и адаптер/модель фронтенда.

## Отзывы

`GET /minors/{id}/reviews` возвращает существующую обёртку `{ items: [...] }`.
Страница майнора использует `id`, `completion_year`, все пять полей `*_rating`,
`experience_text`, `selection_advice` и `created_at` из существующего Go DTO.
Две текстовые части могут быть `null`; четыре оценки показываются отдельно от рекомендации.
Год окончания 2026 отображается как учебный год 2025/26. `created_at` — ISO-дата или `null`.

Для точного переноса ответов анкеты адаптер дополнительно поддерживает необязательное
поле `completion_status`: `completed`, `earlier`, `studying` или `unknown`.
Если поле отсутствует, числовой `completion_year` означает `completed`, а `null` — `unknown`.
Пустой год никогда сам по себе не считается признаком текущего обучения.
Чтобы различать «Раньше» и «Ещё учусь», серверу нужно отдавать отдельный статус;
в рамках этой задачи Go-код и миграции не менялись.

Сводки, процент рекомендаций (оценки 4–5) и распределение рассчитываются из полного
списка опубликованных отзывов. `selection_advice` используется как исходный текст
для блока «Что знать заранее», без автоматически придуманных выводов.

`helpful_count` — необязательное неотрицательное целое или `null`. При его наличии
доступна сортировка по полезности. Отправка голосов на сервер пока не реализована:
«Полезно» активно только в demo и хранится отдельно в localStorage.
Кнопка «Оставить отзыв» на новой странице по текущему решению не открывает форму.

`GET /me/reviews` возвращает текущие поля `id`, `minor_id`, пять `*_rating`,
`experience_text`, `selection_advice`, `status`. Поддержаны статусы `pending`,
`published`, `rejected`; их подписи показываются в «Моих отзывах».

`created_at` и `published_at` поддерживаются как ISO-даты или `null`, `completion_year`
и необязательный `completion_status` — по правилам выше. Если поля отсутствуют, UI не
придумывает дату или статус прохождения. Дополнительно адаптер принимает
`helpful_count` (неотрицательное целое или `null`) и `moderation_note` (строка или `null`).
Эти два поля пока не добавлены в Go; при их отсутствии счётчик и комментарий скрыты.

Личный экран выбирает последний активный отзыв, а при его отсутствии — последний
отклонённый. Прежние записи доступны в истории отправок. Ошибка избранного не блокирует
загрузку личного отзыва; при недоступности каталога текст и оценки остаются видимыми.

`POST /reviews` отправляет поля, которые уже принимает Go:

```json
{
  "minor_id": 42,
  "completion_year": null,
  "difficulty_rating": 3,
  "workload_rating": 4,
  "interest_rating": 5,
  "usefulness_rating": 5,
  "recommendation_rating": 5,
  "experience_text": "Мой опыт обучения",
  "selection_advice": "Совет тем, кто выбирает"
}
```

Ожидается `201 { "id": 100, "status": "pending" }`. Пока запрос выполняется,
компонент формы блокируется; при ошибке введённый текст сохраняется.
Ответ 409 с `{ "error": "..." }` показывается без превращения ошибки в успешное сохранение.
Фронтенд и demo-репозиторий блокируют второй активный отзыв и отзыв на другой майнор.
Повторная отправка возможна после отклонения только на тот же майнор. Go в этой задаче
не менялся: существующее ограничение на один активный отзыв не заменяет серверную проверку
правила «один пользователь — один майнор», её нужно обеспечить на стороне API.
Форма сейчас отключена от интерфейса; новые запросы создания и редактирования страница
«Мои отзывы» не отправляет.

## Избранное

`GET /me/favorites` → `200 { "items": [42, 77] }`.
Порядок `items` — порядок добавления, от ранних к поздним. Баннер «Избранного»
показывает первые три доступных майнора из этого списка независимо от фильтров каталога.
`PUT /me/favorites/42` и `DELETE /me/favorites/42` → `204`, без тела ответа.
Пользователь определяется серверной сессией; фронтенд не отправляет `user_id`.
Изменение сердечка подтверждается после успешного ответа; при ошибке остаётся прежнее состояние.
Demo-избранное не переносится в аккаунт и не смешивается с серверным.

## Ошибки и публикация

Для ошибок используется статус HTTP и JSON `{ "error": "Сообщение пользователю" }`.
Клиент также распознаёт текущий текстовый ответ 401. Невалидный успешный JSON и
ошибки структуры ответа обрабатываются отдельно от HTTP-ошибок.

Vite проксирует `/auth`, `/me`, `/health`, `/minors`, `/reviews` на `BACKEND_URL`.
Для production бэкендеру нужно отдельно настроить раздачу `web/dist`, SPA-маршруты
`/catalog`, `/home` и `/disciplines/:id` и возврат после авторизации на React-каталог. Сейчас Go продолжает
отдавать прежний `web/app.html` на `/`; это не менялось во frontend-задаче.
Фронтенд и API желательно обслуживать с одного origin. Для входа в dev окружении
используйте то же имя хоста, на котором настроен OAuth callback и cookie.

## Проверки

`npm test` проверяет фильтрацию, оба репозитория, HTTP-контракт, cookie credentials,
передачу AbortSignal, 401/409/500, nullable-оценки и локальное хранение. Запросы API в тестах
подменены; это не утверждение о проверенной интеграции с работающим Go-сервером.
`npm run build` проверяет типы и собирает production-версию.
